# Pothub environment variables

Configure these on the **server/API host** unless explicitly marked as a frontend build setting. Never commit real credentials to GitHub.

## Required for GitHub login and AI

| Variable | Required | Purpose |
|---|---|---|
| `GITHUB_CLIENT_ID` | Yes | GitHub OAuth application client ID. |
| `GITHUB_CLIENT_SECRET` | Yes | GitHub OAuth application secret. Server only. |
| `SESSION_SECRET` | Yes | Random secret of at least 32 characters for sessions and native OAuth handoff tickets. |
| `GEMINI_API_KEY` | Yes for AI | Gemini API key for diagnosis and repair proposals. Server only. |
| `SUPABASE_URL` | Yes for persistent accounts/billing/remote alerts | Supabase project URL. |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes for persistent accounts/billing/remote alerts | Supabase service role key. Server only; never use a `VITE_` prefix. |

## Required for Flutterwave v4 USD card billing

| Variable | Required | Purpose |
|---|---|---|
| `FLW_CLIENT_ID` | Yes | Flutterwave v4 client ID. |
| `FLW_CLIENT_SECRET` | Yes | Flutterwave v4 client secret. Server only. |
| `FLW_ENCRYPTION_KEY` | Yes | Flutterwave AES key used by the client-side encryption helper. `/api/billing/config` supplies it to the client only when billing credentials and Supabase are configured. This is not the secret API credential. |
| `FLW_MODE` | Yes for chosen environment | Use `sandbox` for tests; set `production` only after account approval and successful sandbox tests. |

Pothub sends the charge in USD. The issuer may convert it into the cardholder's local currency, but no provider can guarantee that every card/country is supported or accepted.

## Optional server settings

| Variable | Purpose |
|---|---|
| `GEMINI_MODEL` | AI model name; defaults to `gemini-2.5-flash`. |
| `APP_URL` | Canonical public origin used for OAuth callback and payment return URL. Set this to the deployed HTTPS domain. |
| `APP_ORIGIN` | Allowed browser origin for cross-origin API requests. Usually the deployed HTTPS domain. |
| `PORT` | Local server port; defaults to `8787`. Normally managed by the hosting provider. |

## Optional remote notifications

| Variable | Purpose |
|---|---|
| `VERCEL_WEBHOOK_SECRET` | Secret generated by Vercel when configuring the webhook at `/api/webhooks/vercel`. |
| `GITHUB_WEBHOOK_SECRET` | Secret set on the repository webhook targeting `/api/webhooks/github`. |
| `VAPID_PUBLIC_KEY` | Public Web Push key; served to browsers for subscription setup. |
| `VAPID_PRIVATE_KEY` | Private Web Push key; server only. |
| `VAPID_SUBJECT` | Contact email/URL for Web Push, e.g. `mailto:admin@example.com`. |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | Firebase Admin service account JSON as one environment variable, server only. Android also needs the matching `google-services.json` file in the generated native project. |

Generate Web Push keys with `npx web-push generate-vapid-keys`. Keep the private VAPID key and Firebase service account JSON private.

## Optional frontend setting

| Variable | Purpose |
|---|---|
| `VITE_API_BASE_URL` | Public API base URL embedded at frontend build time. Not a secret. Usually leave blank when the web frontend and API share a domain. For the standalone APK, users can save the deployed HTTPS API URL in Settings instead. |

## Setup checklist

1. Copy `.env.example` to `.env` for local development and fill the variables for the features you want to test.
2. Run `supabase/schema.sql` in the Supabase SQL editor before testing persistent credits, payment orders, or remote notifications.
3. Configure the GitHub OAuth callback as `https://YOUR-DOMAIN/api/auth/github/callback`.
4. Test Flutterwave using sandbox credentials and test cards first. Do not switch `FLW_MODE` to `production` until the account, currency, card authorization and webhook flows are approved and verified.
5. For remote push, configure HTTPS, Web Push keys and/or Firebase Cloud Messaging, then configure the Vercel/GitHub webhooks. Without a webhook, deployment polling only runs while Pothub is open.

## Gemini failover
Configure `GEMINI_API_KEY`, `GEMINI_API_KEY_2`, and `GEMINI_API_KEY_3` on the server. Each configured key is tried in order when the preceding request fails. `GEMINI_MODEL`, `GEMINI_MODEL_2`, and `GEMINI_MODEL_3` select each route model; route-specific model values fall back to `GEMINI_MODEL`, then `gemini-2.5-flash`. Never expose these values with `VITE_` prefixes.

## New-user credits and device abuse
New profiles start with 25 credits. The backend stores only a SHA-256 hash of the browser/app device ID for a basic one-device free-credit limit. This is an abuse signal, not a perfect device identity: clearing browser storage, changing devices, or using a modified client may bypass it. Apply the updated `supabase/schema.sql` before deploying.

`VITE_NGN_PER_USD` is an optional public display-only rate used to show an approximate naira equivalent beside USD packs. It is not used for charging or verification; the current Flutterwave flow charges USD. Leave blank to show that the card issuer sets the conversion rate.

## Optional Vercel OAuth

| Variable | Purpose |
|---|---|
| `VERCEL_CLIENT_ID` | Vercel OAuth application client ID. |
| `VERCEL_CLIENT_SECRET` | Vercel OAuth application secret; server only. |
| `VERCEL_REDIRECT_URI` | Exact registered callback, e.g. `https://YOUR-DOMAIN/api/auth/vercel/callback`. If blank, it is derived from `APP_URL` or the request origin. |
| `VERCEL_OAUTH_SCOPES` | Optional explicit scope list. If blank, Vercel uses the scopes configured for the app. Configure only the required user/project/deployment permissions in the Vercel dashboard and verify that the returned token can access the intended API endpoints. |

The callback stores access and refresh tokens encrypted at rest using `SESSION_SECRET`. Refresh tokens rotate when refreshed. The `vercel_connections` table must exist (run the updated schema). The user-supplied local token remains available as a fallback, but OAuth is preferred for a public multi-user service.


## AI cost and response limits

| Variable | Purpose |
|---|---|
| `AI_MAX_PROMPT_CHARS` | Maximum prompt length (default 60,000 characters; server caps it at 90,000). |
| `AI_MAX_OUTPUT_TOKENS` | Maximum requested output (default 3,072; server caps it at 4,096). |
| `AI_MAX_OPERATION_COST_USD` | Estimated upper cost ceiling per AI call (default $0.12). Routes estimated above the ceiling are skipped. |
| `GEMINI_INPUT_USD_PER_MILLION`, `GEMINI_OUTPUT_USD_PER_MILLION` | Assumed Gemini input/output token prices used for preflight cost estimates. Update these to match the exact selected model and current provider pricing. |
| `AI_FALLBACK_INPUT_USD_PER_MILLION`, `AI_FALLBACK_OUTPUT_USD_PER_MILLION` | Assumed input/output prices for the OpenAI-compatible fallback. |

These estimates are safeguards, not a verified 60% net-profit guarantee. Token estimates and provider prices can change; compare actual invoices, payment fees, taxes, hosting, refunds and support costs before launch. If model pricing changes, update the environment prices before enabling that model.
