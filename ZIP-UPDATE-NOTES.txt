POTHUB — REPOSITORY LOADING, VERCEL OAUTH, API ERROR HANDLING & PICKER UPDATE

What changed
1. Added a dedicated Next.js API route for GET /api/github/repos. It no longer has to boot the large Express catch-all before returning repositories. GitHub 401/403/API errors and timeouts now return JSON with a request ID and a useful next step.
2. Added dedicated Next.js routes for Vercel connect/callback. OAuth state is signed and verified with Node's built-in HMAC-SHA256 crypto, includes expiry checks, and does not dynamically import @hapi/iron just to begin OAuth.
3. Added a dedicated Vercel API route for status, disconnect, projects, deployments and logs. Errors are JSON with request IDs. Vercel OAuth credentials accept the existing supported environment-variable aliases.
4. Fixed browser-session cookie updates to preserve multiple Set-Cookie headers and to avoid relying on Express-only response.append() behavior in Next.js API handlers.
5. Vercel callback now updates the opaque browser session (pothub_sid) when the user is using browser OAuth, rather than writing a separate legacy session cookie that the browser session would ignore.
6. Styled all select/picker controls with Pothub's dark/light theme, custom chevron, focus/hover states and consistent sizing. Native mobile option sheets can still be rendered by the Android browser/OS.
7. Improved the frontend message for non-JSON API errors so it explains what to inspect rather than suggesting only that the route might be missing.

Configuration reminders
- Set APP_URL to https://pothub-self.vercel.app (origin only, no path).
- Set the Vercel OAuth application's callback URL to https://pothub-self.vercel.app/api/vercel/callback exactly.
- Keep the existing VERCEL_CLIENT_ID / VERCEL_OAUTH_CLIENT_ID / VERCEL_APP_CLIENT_ID and corresponding client-secret environment variables. Do not expose the client secret in frontend code.
- SESSION_SECRET must be at least 32 characters and must remain stable across deployments while sessions are active.
- GitHub sign-in still uses GitHub OAuth. Google creator sign-in remains Firebase Authentication. Vercel connection requires a signed-in GitHub Developer session.
