# PotHub workspace crash and deployment verification

## Reported runtime error

`Cannot access 'eY' before initialization` is a minified JavaScript temporal-dead-zone error. The identifier `eY` is generated by the production bundler and cannot be mapped to a source variable from the stack trace alone. It is not sufficient evidence to claim that a particular source line is the cause.

## Source and deployment safeguards

- `WorkspaceSection.jsx` imports the provider registry exports it uses. The current source does not reproduce the reported `eY` identifier, so the exact source-level cause remains unconfirmed.
- Deployment/commit identifiers are embedded into the client bundle and exposed by `/api/version` with no-store headers.
- The app checks for a mismatched web deployment and refreshes stale client code; the service worker does not cache Next.js chunks.
- This ZIP must be deployed to Vercel before these safeguards can affect `pothub-self.vercel.app`.

## Verification limitation

A source ZIP cannot prove which deployment the live URL is serving. After deployment, compare the Vercel production deployment commit with the ZIP source and load `/api/version` to confirm the live deployment identity. A clean production build and live browser reproduction are still required to conclusively map the minified stack to a source line.
